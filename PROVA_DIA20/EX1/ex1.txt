Sistema de Frete — Estilo "Apólice" (com RFs) 📦
Vou fazer no mesmo formato do professor: contexto, RFs, RNFs, tarefa, critérios. Mesma pegada, mas mais fácil.

Contexto de negócio
Uma transportadora de médio porte precisa reformular o sistema de cálculo de fretes. Hoje, o código usa uma sequência de if/else que cresce a cada novo modal (terrestre, aéreo, marítimo, expresso). A diretoria exige que novos modais possam ser adicionados sem alterar nenhuma classe existente — apenas adicionando classes novas.

Especificação funcional
RF01 — Frete Terrestre
O custo é calculado por peso × 2.0. Fretes terrestres com peso acima de 100 kg recebem acréscimo de 10% sobre o custo. O recibo deve conter o tipo do frete, o peso e o custo final.

RF02 — Frete Aéreo
O custo é calculado por peso × 5.0. Fretes aéreos com peso acima de 50 kg recebem acréscimo de 20% sobre o custo. O recibo segue o mesmo padrão do terrestre.

RF03 — Frete Expresso
O custo é calculado por peso × 8.0. Não há acréscimo por peso — o valor já é fixo por kg. O recibo segue o mesmo padrão.

Requisitos não funcionais
RNF01 — novos modais devem poder ser adicionados sem alterar classes existentes (Open/Closed).

RNF02 — o sistema deve gerar, para todo frete processado, um recibo padronizado contendo tipo, peso e custo.

RNF03 — a classe cliente não pode usar if/switch para decidir o tipo de frete.

Tarefa
Implemente o sistema usando Factory Method (GoF), com a seguinte estrutura:

Interface Frete com os métodos calcularCusto(double peso) e gerarRecibo(double peso).

Classes concretas FreteTerrestre, FreteAereo, FreteExpresso implementando Frete.

Classe abstrata CriadorFrete com:

método abstrato criarFrete()

método concreto processar(double peso) que usa apenas a abstração Frete

Subclasses concretas CriadorTerrestre, CriadorAereo, CriadorExpresso.

Classe Main que processe um frete de cada tipo e imprima o recibo.

Entregáveis
Implementação Java completa e compilável.

Classe Main que emita pelo menos um frete de cada tipo e imprima o recibo.

Critérios de avaliação
Aplicação correta do Factory Method, com o método fábrica isolado nas subclasses de criador.

Implementação fiel das regras de RF01, RF02, RF03 (incluindo acréscimos por peso).

Ausência de if/switch decidindo tipo de frete no cliente ou no criador abstrato.

Código compilável e executável.
